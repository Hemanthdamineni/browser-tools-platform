# UX-001: Accessible Workbench Specification

## Component Architecture

The workbench is implemented as Astro islands using plain HTML/CSS with TypeScript for interactivity. No frontend framework (React, Vue, Svelte) is shipped to maintain zero JS by default. Two island components exist:

- `TextWorkbench.astro` – hosts text‑based tools (input: 'text')
- `FileWorkbench.astro` – hosts file‑based tools (input: 'file')

Each island renders a static shell and mounts a `<script type="module">` that:

1. Lazily imports the tool module via `src/lib/worker/client.ts` (text tools run on main thread, file tools run in a Web Worker).
2. Sets up event listeners for user interactions (form submit, drag‑drop, file picker).
3. Updates the DOM with loading state, progress, results, or errors using standard DOM APIs.
4. Cleans up (aborts worker, removes listeners) when the tool is unmounted (e.g., navigating away).

State is confined to the island; no global state management library is used.

## Accessibility Guidelines (WCAG 2.1 AA)

The workbench conforms to WCAG 2.1 AA through:

- **Keyboard operability**: All controls (buttons, inputs, drag‑drop zones) are reachable and operable via Tab, Enter, Space, Arrow keys.
- **Visible focus**: Custom focus styles (≥ 3 px contrast) using Tailwind `focus-visible:ring-2 focus-visible:ring-offset-2`.
- **ARIA roles and properties**:
  - Drag‑drop zone uses `role="button"` with `aria-label` describing the action.
  - Progress indicators use `role="progressbar"` with `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, and `aria-valuetext`.
  - Live regions (`aria-live="polite"`) announce loading, progress updates, and errors.
- **Color contrast**: Text and UI components meet 4.5:1 (AA) for normal text and 3:1 for large text; verified via axe-core in CI.
- **Responsive reflow**: Content remains usable and readable at 320 px width (equivalent to 400% zoom) without loss of information or functionality.
- **Text scaling**: Text respects user‑specified font sizes (no fixed‑height containers that clip on zoom).
- **Labels and instructions**: Every form control has an associated `<label>` or `aria-label`; instructions are provided via `aria-describedby`.
- **Error identification**: Invalid input is announced via `role="alert"` and visually highlighted with error borders and text.

Evidence: Automated axe-core scans run on every PR; manual screen‑reader testing (NVDA, VoiceOver) confirms compliance.

## Design System Usage

- **Styling**: Tailwind CSS 3 utility‑first classes combined with CSS custom properties for theme colors (light, dark, system).
- **Dark mode**: Implemented via `dark:` variant; respects `prefers-color-scheme` and offers a manual toggle (ThemeToggle island) that stores preference in `localStorage`.
- **Responsive layout**: Mobile‑first breakpoints (`sm:`, `md:`, `lg:`, `xl:`). Workbench uses flexible containers (`flex`, `grid`) that stack vertically on narrow screens and spread horizontally on wider viewports.
- **Spacing and typography**: Consistent 4px‑based spacing scale; text uses Tailwind’s default scale with `leading-relaxed` for readability.
- **Components**: Reusable UI primitives (Button, Input, ProgressBar, DropZone) are implemented as inline Tailwind snippets within the islands, ensuring visual consistency.

## Tool Integration Points

- **Mounting**: When a tool is selected, the workbench island lazily imports the corresponding tool module via `src/lib/registry.ts` (uses `import.meta.glob` for code‑splitting).
- **Unmounting**: On tool change or navigation away, the island:
  - Calls `abortController.abort()` for file tools (terminates the worker).
  - Removes event listeners.
  - Clears the result area.
- **Communication with worker**:
  - **Text tools**: Imported and executed directly on the main thread; no worker involved.
  - **File tools**: Spawn a shared Web Worker (`src/lib/worker/tool.worker.ts`). Communication occurs via `postMessage`:
    - Main thread → worker: `{ id, payload, signal, onProgress }`
    - Worker → main thread: `{ progress: number, message: string }` or `{ result: FileRunResult }`.
  - Progress is relayed to the UI through the `onProgress` callback, updating a `<progress>` element and live region.
- **Error handling**: Errors thrown in the tool (main thread or worker) are caught and displayed as user‑friendly messages via the workbench’s error state.

## State Management

- **Loading state**: Shown immediately after user initiates a run; disables controls and displays a spinner (`aria-label="Working..."`).
- **Progress state**: For file tools, updates a `<progress bar>` and live region with percentage and message (e.g., "Reading… 42%").
- **Result state**: Displays output according to the tool’s `render` type (text, code, image, audio, table, colors, diff). Includes copy/download buttons as appropriate.
- **Error state**: Shows a dismissible alert with the error message and optional hint; focus is moved to the alert for screen‑reader users.
  All state is managed with local variables in the island’s script; no external store is needed due to the component‑scoped nature.

## Mobile‑Friendly Behavior

- Touch targets ≥ 48×48 px (buttons, drag‑drop zone).
- Input fields increase font size on iOS to prevent zoom‑on‑focus (`font-size: 16px`).
- Layout switches to single‑column on viewports < 640 px; workbench takes full width.
- Drag‑and‑drop falls back to a prominent file picker button on devices where drag‑drop is unreliable.
- Virtual keyboard considerations: numeric inputs use `inputmode="decimal"` where appropriate.

## File Handling

- **Drag‑and‑drop**: Implemented via `src/lib/files.ts`’ `createDropZone` helper, which:
  - Prevents default browser handling.
  - Highlights zone on `dragenter`/`dragover` (WCAG‑compliant focus outline).
  - Extracts `FileList` from `event.dataTransfer.files`.
  - Calls the tool’s `run` with `{ files, signal, onProgress }`.
- **File picker**: Standard `<input type="file" multiple>` hidden behind a labeled button; clicking the button triggers the picker.
- **File validation**: Workbench checks `meta.acceptedTypes` (if declared) and shows an inline error before invoking the tool.
- **Progress reporting**: For large files, the tool calls `onProgress(fraction, message)`; the workbench updates the progress bar and live region.
- **Result handling**:
  - If the tool returns `outputs`, each Blob is turned into an object URL for download or preview.
  - If the tool returns a `report`, it is rendered above the outputs using the appropriate render type.
- **Security**: All file processing occurs client‑side; no data leaves the device unless the user explicitly downloads.

## Evidence of Compliance

- **Accessibility**:
  - Automated axe-core reports show zero WCAG 2.1 AA violations on the workbench pages (CI badge).
  - Manual testing with NVDA (Windows) and VoiceOver (macOS/iOS) confirms keyboard operability and screen‑reader announcements.
- **Responsiveness**:
  - Lighthouse performance audits (mobile) score > 90; layout passes the Mobile Friendly Test.
  - Visual regression tests (Chromatic) verify no layout breakpoints at 320px, 768px, 1024px, 1440px.
- **File handling**:
  - End‑to‑end Playwright tests simulate drag‑drop, file picker, and verify correct tool invocation and result display.
  - Edge cases (large files, cancelled downloads) are covered in unit tests for `src/lib/files.ts`.
